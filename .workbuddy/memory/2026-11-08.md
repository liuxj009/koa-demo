# 2026-11-08

## 修复 /encrypt 接口 RSA OAEP 解码失败

- 现象：`Error: error:02000079:rsa routines::oaep decoding error`，抛在 `utils/index.js:31` 的 `privateDecrypt`。
- 根因：前端 `web/helper.js` 用的 jsencrypt 只实现 PKCS#1 v1.5，服务端 `utils/index.js:35-36` 用 `RSA_PKCS1_OAEP_PADDING` + `oaepHash: 'sha256'`，padding 格式不匹配，OpenSSL 在 `rsa_padding_check_PKCS1_OAEP_mgf1` 校验阶段失败。
- 处理：`web/helper.js` 整体重写为浏览器原生 `crypto.subtle`（`RSA-OAEP` + `SHA-256`，`importKey` 用 spki，兼容 pkcs1 头），导出改为 async；`web/index.js` 的 encrypt 点击改为 async/await，去掉会把密文多包一层双引号的 `JSON.stringify`。
- 服务端 `server.js` / `utils/index.js` 未改动。

## 结论沉淀

- JSEncrypt 无 OAEP 能力（能力边界，非配置项）；浏览器侧支持 OAEP 的可靠选择是原生 crypto.subtle，其次是 node-forge（默认 md 为 SHA-1，必须显式指定 sha256 且 mgf1 同步）。
- `crypto.subtle` 依赖 Secure Context，仅 https / localhost 可用；用局域网 IP 走 http 调试时不可用。
- RSA-OAEP(SHA-256) 单块明文上限 190 字节（256 − 2×32 − 2），长报文需 RSA + AES 混合加密。
- 服务端每次启动 `generateKeyPairSync` 生成新密钥对（`server.js:10`），刷新进程后前端持有的旧公钥会导致同样的 padding 报错。
